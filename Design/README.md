# 0.4.0 — UI 개편

디자이너 없이 개발자 한 사람이 화면 19개를 대대적으로 고치는 작업의 **판단 기록**입니다.
코드가 아니라 결정을 적습니다 — 코드는 `Cutin/DesignSystem/`이 진실이고, 여기는 왜 그렇게 했는지.

- 기준선: [감사 2026-08-17](audit-2026-08-17.md) · 콘택트 시트 [라이트](audit-2026-08-17-light.jpg) / [다크](audit-2026-08-17-dark.jpg)
- 다시 찍는 법: `Scripts/audit/README.md`

## 원칙 셋

1. **Figma를 만들지 않는다.** 디자이너가 없는데 Figma를 만들면 두 번 일한다. SwiftUI `#Preview`와
   시뮬레이터 스크린샷이 디자인 도구다. 미적 판단이 필요한 자리는 2~3안을 Preview로 나란히 만들어 **고른다** — 고르는 건 빠르고 만드는 건 느리다.
2. **iOS 26 네이티브를 최대한 빌린다.** 탭바·네비게이션·시트·검색·컨텍스트 메뉴·Form은 시스템 것.
   커스텀은 브랜드가 드러나는 자리(사진 대우·타이포·색·빈 상태·첫인상)에만 쓴다. 애플보다 잘 만들 시간이 없다.
3. **컴포넌트 카탈로그가 진실의 원천.** 화면을 고치기 전에 부품을 고치고, 부품이 바뀌면 전 화면이 따라오게 한다.
   `#if DEBUG` 갤러리 화면에 모든 컴포넌트를 라이트/다크·Dynamic Type별로 늘어놓는다.

## 브리프 (0단계) — 결정할 것

감사가 말해 준 것: **주인공은 사진이고, 크롬은 조용해야 하고, 그런데 지금은 조용한 게 아니라 비어 있다.**

| 결정 | 선택 | 상태 |
|---|---|---|
| **포인트 색** | **잉크(모노크롬 정제, A)** — 켜진 것(고른 칩 · 내 반응 · 미읽음 점 · 핀 배지)은 옅은 면 + 잉크 테두리 + 굵은 글씨로 가른다. 처음엔 3안 비교로 웜 코랄(B)을 골랐다가 앱에서 보고 **잉크로 되돌림**(사용자 결정 2026-08-17 저녁). `brand*` 토큰 이름은 남기고 값만 잉크 — 켜진 것의 색을 한 곳에서 바꾸는 손잡이 | ✅ 2026-08-17 |

| **앱 아이콘** | 파랑·라벤더·보라 꽃잎 4장(글래스) **유지** — 인트로가 이 마크를 그대로 피우고, 앱 안은 잉크라 색이 부딪히지 않는다 | ✅ 2026-08-17 |

## 토큰 요약 (진실은 `Cutin/DesignSystem/`)

| 묶음 | 값 | 규칙 |
|---|---|---|
| 크롬 | `bg` `surface` `surfaceSunken` `surfaceRaised` `border` `borderStrong` `textPrimary` `textSecondary` `accent`(잉크) | 위계는 FILL/OUTLINE/WEIGHT/SIZE. CTA는 `accent` 채움 하나 |
| 켜진 것 | `brand`(테두리·점·배지 = 잉크) `brandInk`(글자·아이콘 = 잉크) `brandSoft`(켜진 칩의 면 = sunken) | **켜진 것에만.** 옅은 면 + 잉크 테두리 + 굵은 글씨. 이름이 brand인 이유는 토큰 머리말 |
| 타이포 | largeTitle 28 · title 22 · headline 17 · subheadline 15 · body 15 · bodyText 14(이행 중) · label 13 · caption 11 · chip 12 · buttonLabel 15 · numeric(Geist) · logo(Geist) | 임의 크기 없음 — 필요하면 단계를 늘린다 |
| 움직임 | `Motion.quick` `.standard` `.emphasized` · `Duration.fast` `.medium` | 손끝 / 화면 안 / 화면 전환 |
| 표면 | `raised()` | 카드는 이걸로 뜬다. 그림자 값을 화면이 고르지 않는다 |

## 결정 기록

- 2026-08-17 — 0.3.0(#30)을 dev에 병합하고 태그는 #37이 닫힐 때. 개편은 `release/0.4.0`에서 시작.
- 2026-08-17 — 감사 도구를 `Scripts/audit/`에 둔다(하니스와 같은 규칙: 앱 타깃 밖, 훅은 커밋하지 않음). before/after를 같은 데이터로 찍기 위해서다.
- 2026-08-17 — **포인트 색은 웜 1색(B).** 3안을 같은 화면 조각으로 그려 비교: A(모노크롬 정제)는 켜진 것이 늦게 읽히고, C(프레임 색 번짐)는 흰 프레임·설정 화면처럼 번질 색이 없는 자리에서 규칙이 반쪽이 된다. B만 전역에 일관되게 적용된다. 레퍼런스는 BeReal · setlog.
- 2026-08-17 — 웜 포인트는 **CTA에 쓰지 않는다.** 켜진 상태와 누를 것이 같은 색이면 감사 G1이 색만 바뀐 채 되돌아온다.
- 2026-08-17 — `brand`를 빨강(`danger`)에서 색상환 반 단 떨어뜨렸다(코랄→살짝 주황). 켜짐과 위험이 같은 색이면 안 된다.
- 2026-08-17 — 로그인 히어로와 팁 그림은 **사진을 번들하지 않고** `StripArt`로 그린다. 로그인 전에는 서버 템플릿을 받을 수 없고, 남의 사진으로 첫인상을 만들면 안 된다. 합성기와 같은 비례라 들어가서 보는 것과 같은 물건이다.
- 2026-08-17 — 상세의 댓글은 **한 번에 보인다.** 별도 화면(`CommentsView`·`Route.comments`)을 없앴다 — 두 번 들어가야 대화가 보이는 SNS는 없다. 부가 동작(공유·사진 저장·보관)은 상단 ⋯ 메뉴로 — 본문은 사진과 대화다.
- 2026-08-17 — 카드의 반응은 **받은 이모지를 겹쳐 쌓고 총수**만. 다섯 개를 다 늘어놓는 건 상세의 일이다. 둘 다 없으면 줄이 없다 — 빈 줄에 "아직 없음"을 적으면 조용한 카드가 쓸쓸한 카드가 된다.
- 2026-08-17 — **인트로는 기다리는 시간을 새로 만들지 않는다.** 앱 시작의 `/users/me` 왕복 구간(0.3.0은 빈 배경)을 덮는 덮개로만 — 최소 0.95초는 연출이 끝까지, 서버가 늦어도 1초 안팎에서 넘어간다. 리듬은 연속 촬영 3·2·1(120ms), 넷째 칸이 웜 + 햅틱 한 번, 워드마크는 넓은 자간에서 조여든다.
- 2026-08-17 (저녁) — **포인트 색을 잉크로 되돌림.** 사용자가 앱에서 보고 "핀 등의 포인트 색을 전부 검정(다크는 흰색)으로". 켜진 것은 옅은 면 + 잉크 테두리 + 굵은 글씨(A안). 토큰 이름 `brand*`는 유지하고 값만 바꿔 화면 코드는 그대로 — 핀 배지의 핀만 `accentOn`으로(다크에서 흰 원 위 흰 핀 방지).
- 2026-08-17 (저녁) — **인트로는 아이콘 그대로.** 네모 넷은 아이콘과 딴판이었다(사용자 지적). 아이콘 문서(`AppIcon.icon`)의 꽃잎 SVG 좌표·색·이동값을 `AppMark`로 옮겨 한 장씩 피운다. 아이콘 방향은 유지로 확정.
- 2026-08-17 — 촬영 설정의 기본은 **네 컷**(앱의 이름). 배치는 설정에서 글리프로 미리 보고 고르며, 찍고 나서도 바꿀 수 있다고 적는다. 보정 타일은 첫 컷에 실제 매트릭스를 돌린 미리보기 — 보이는 것과 결과가 같다.
- 2026-08-17 — 미리보기의 "댓글"은 상세를 **입력칸에 포커스한 채로** 연다(`Route.postComments`), 카드를 누르면 상세.
- 2026-08-17 — 프로필의 큰 제목을 **인라인**으로. 큰 제목 + `refreshable` + 화면보다 짧은 내용에서 위로 밀면 제목이 반쯤 접힌 채 되돌아오지 않고 실기기에서는 접힘/펼침이 반복되며 상단이 떨렸다(사용자 신고). 이름·아바타가 이미 머리라 잃을 것이 없다.
- 2026-08-17 — 그리드 셀을 **길게 누르면 미리보기 팝업**(`PostPeekView`) — 스크림 위에 카드(합성본은 화면 절반까지) + 글래스 막대(댓글 · 공유 · 보관 · 내 것이면 고정 해제). 스크림을 누르면 닫힌다. 컨텍스트 메뉴가 아닌 이유: 셀이 대표 컷 한 장뿐이라 "어느 포스트인지"부터 크게 보여야 한다. 셸(`RootView`)이 그린다 — 탭바·내비게이션 바까지 어두워지려면 탭 트리 위여야 한다.
- 2026-08-17 — 고정 해제는 `PATCH /posts/{id} { thumbnailCutIndex: 0 }`. 서버가 발행 뒤 이 필드만 받도록 cutin-backend#14를 열었다 — 그 전 서버는 `POST_NOT_DRAFT`를 내고 팝업이 서버 문구를 그대로 보여준다.
- 2026-08-17 — 카탈로그는 Debug 빌드의 프로필 메뉴에서 연다. 앱 안에 있어야 실제 토큰·부품으로 그려지고, Debug에만 있어야 사용자에게 안 보인다.
